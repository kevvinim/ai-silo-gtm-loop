# 실행 리허설 (루프를 실제로 켜기 전에 1회)

오프라인 테스트로는 증명할 수 없는 것이 있다. 새 세션의 에이전트가 이 저장소만 보고 실제 도구(Chrome, Notion, Vercel)로 지시문을 따라 하는지다. 리허설은 공개 게시 없이 30–40분 걸린다.

0. **준비:** Notion Post Queue에 `Posted at`(날짜) 속성을 추가한다. 하루 상한을 셀 때 이 값을 쓴다.
1. **사람:** Vercel에서 Analytics를 켜고, 휴대폰으로 테스트 링크 3개를 연다.
   - `?utm_source=test&utm_content=T1`, `T2`, `T3`
2. **실행 1** (1회성 예약 작업, 새 세션): 감지와 초안, 게이트까지 한다. 초안 제목에 `TEST`를 붙인다.
3. **실행 2** (시험 모드): 다음 행을 일부러 심어 둔다.
   - 승인 안 된 행
   - 차단됐는데 체크된 행
   - 승인된 X 게시물 4개

   통과 조건은 이렇다. X 작성 창에 1건만 채우고 **Post는 누르지 않는다**. 나머지는 이유를 남기고 건너뛴다. 증거로 화면을 캡처한다.
4. **실행 3:** 테스트 방문 3건이 T1, T2, T3로 정확히 집계되어야 한다. 자동화 브라우저로 한 방문은 0건이어야 한다. 학습 결과는 테스트 구역에만 기록한다.
5. **정리:**
   - 심어 둔 행은 Failed로 바꾸고 `TEST · do not post`를 남긴다. 큐를 다시 조회해 게시될 행이 0개인지 확인한다.
   - 실제 학습 로그가 d0에서 끝나는지 확인한다.
   - X 임시저장함이 비어 있는지 확인한다.
   - 테스트 방문(`utm_source=test`)은 모든 집계에서 뺀다.
