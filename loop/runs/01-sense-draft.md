# 실행 1: 감지 → 초안 → 게이트 (매일 08:47 KST)

> 예약 작업으로 매번 새 세션에서 실행된다. 이 파일만 읽고 처음부터 끝까지 할 수 있어야 한다.

**역할:** 너는 "AI 사일로 진단" GTM 루프의 아침 실행이다. 오늘 게시할 초안을 만들고, 독립 게이트를 통과시켜 승인 큐에 올린다.

**필요한 것:**
- Notion: 플레이북 페이지와 Post Queue 데이터 소스 `collection://fdd1b185-2333-4075-9afb-ce5a5150bdc0`
- Claude in Chrome: X와 Threads에 로그인된 상태
- 스킬: korean-unslop

## 단계
1. **기준 읽기.** 플레이북 페이지 전체를 읽는다: 규칙, 앵글, 링크 태그, 학습 로그. 학습 로그 맨 위 줄에서 오늘의 앵글 가중치를 정한다. 오늘 일차(d)는 2026-10-24를 d0으로 센다.
2. **감지.** Chrome에서 플레이북의 감지 쿼리마다 검색한다.
   - Threads: `https://www.threads.com/search?q=<쿼리>`
   - X: `https://x.com/search?q=<쿼리>&f=live`
   - 48시간 안에 실제 사람이 이 문제를 이야기한 게시물을 최대 15개 고른다. 각각 URL, 작성자, 대략의 팔로워 수, 한 줄 요약을 남긴다.
   - 정치, 사건·사고, 광고 계정은 뺀다.
   - 그들이 쓴 표현 가운데 새로운 것은 메모해 둔다. 초안에 쓸 재료다.
3. **물량 정하기.**
   - 채널별 게시물: Threads 2–3개, X 2–3개, LinkedIn 0–1개
   - 사람이 게시하는 채널(초안과 작성 창만 준비): Instagram 카드뉴스 0–1개, 네이버 블로그(주 3편), 브런치(주 1편), 커뮤니티(README의 일정표대로 하루 1곳)
   - 답글: Threads와 X에 각각 최대 5개
   - 앵글은 가중치 비율대로 나눈다.
4. **초안 쓰기.** 감지한 그들의 말로 쓴다.
   - 게시물에는 태그된 링크를 넣는다. `utm_content`는 앵글+번호다.
   - 답글은 조언을 먼저 쓰고, 링크는 3개 중 1개에만 넣는다.
   - korean-unslop의 A층 신호(안심어, 서비스 존대, 연결 어미 뒤 쉼표)를 확인한다.
   - 숫자, 성과, 1인칭 경험은 지어내지 않는다.
   - 같은 앵글 안에서도 전날과 다른 문장을 쓴다.
5. **큐에 올리기.** 각 초안을 Post Queue에 한 행씩 추가한다.
   - 채울 칸: Draft(`d{일차} · 채널 · 앵글번호 · 짧은 제목`), Channel, Type, Angle, Text, Tagged link, Reply to URL(답글일 때), Day
   - Status는 Drafted로 둔다.
6. **게이트.** 두 겹으로 검사한다.
   - **기계 검사(코드):** 오늘 행을 `drafts.json`으로 저장하고 `node loop/check.js gate drafts.json`을 실행한다. 링크 태그, X 길이, 금지 표현, 출처 없는 인용을 잡는다. 여기서 BLOCK이면 그대로 Blocked이고, 사람도 에이전트도 뒤집지 않는다.
   - **판단 검사(에이전트):** 기계 검사를 통과한 행만 초안을 쓰지 않은 **별도 에이전트**에게 맡긴다.
   - 그 에이전트가 오늘 행을 플레이북 규칙으로 하나씩 검사한다.
   - 통과한 행은 Gate notes를 `PASS · 이유`로 쓴다.
   - 실패한 행은 Status를 Blocked로 바꾸고 Gate notes를 `BLOCK · 어긴 규칙과 해당 문구`로 쓴다.
   - 게이트 결과를 직접 고치지 않는다.
7. **알림.** Kevin에게 짧게 알린다(푸시 알림 또는 마지막 메시지): "오늘 초안 N개 · 통과 M개 · 차단 K개, Notion에서 Approved 체크해 주세요" + 큐 링크.
